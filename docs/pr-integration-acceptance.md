# PR 整合版实端验收

适用：1.3.6，即已发布 1.3.5 之后的稳定性整合（2026-10-20）与本地意图规则修复（2026-10-29）。图片读取、荣格八维、语音转写、Android 和 Mac 不在本轮；保留现行 API 标签展示，MBTI 使用已批准的 v4 独立四轴规则。

## 本轮优先验收

1. **聊天助手发送与恢复**：打开右侧助手，保留原有狗头军师及 Skills。发送消息、停止、再发送，以及关闭重开后都应可继续使用；刷新后不应恢复无法停止的“回答中”。本机 OpenAI 兼容服务及 Ollama 可以不设密钥，远程服务仍按原要求保存密钥。
2. **助手独立模型**：在助手顶部模型菜单选择已保存的 API 档案，主聊天仍可使用本地 Laya。菜单的“默认 API”表示使用此前保存的默认 API 档案，不表示让 Laya 生成聊天。切换助手模型不切换意图分析来源，不取消正在生成的三个候选；运行中的助手先停止后再切换。重命名只更新显示，更换或清除该助手密钥、删除其档案会停止旧请求。
3. **真实等待状态**：读取资料、整理上下文、调用模型只显示实际发生的阶段和消息数，回答流式出现后收起阶段列表。意图、画像和三个回复选项在忙碌时显示小型加载指示，结束或报错后停止。
4. **启动与清理**：按文档使用 Windows 虚拟环境从源码启动，不再因一层 Python 重定向器误判身份；关闭后不应残留本实例分析进程。启动失败提供固定原因代码，不把聊天、密钥或原始输出写进错误记录。
5. **读取与画像续跑**：微信新建的空消息分片不应拖垮整个账号；切账号时数据接口不再等待持锁的模型清理；成员画像在已有覆盖结果与旧分段游标冲突时继续处理。若未完成的游标消息已消失，会明确提示重置该画像，不擅自跳过未读内容。
6. **配置与接口兼容**：较长模型 ID 可保存；服务不支持流式请求时可以回退普通响应，过大错误响应会被拒绝。分析 A、助手 B 各自使用自己的配置；三个候选仍使用分析 API 模型，并继承当前助手模板与 Skills。

本轮保留现有加密格式及已发布数据读取兼容，只修复损坏冗余密钥备份导致结果库无法打开的问题。没有执行数据解密迁移、取消加密或解除旧版本降级限制；这些需要独立方案和验收。

## 1.3.5 已有功能回归


1. **多模型档案**：保存两个不同 API 档案，分别测试、启用、切换、编辑和删除。编辑 B 不会借用 A 的密钥；只改名字不清缓存，换模型使用独立结果，切回原模型恢复原结果。活动档案真正更换密钥后取消旧凭据任务，已有结果和来源缓存标识保留；相同密钥或只改名称不会无故取消。保存并启用走先保存、再启用的完整流程，失败保留原有效选择。
2. **可控分析范围**：添加会话与请求分析分别保存。没有主动请求的会话不因浏览、达到文本数或后台轮询自动开启分析；后台开关初始关闭。顶部“意图识别”开启后分析当前会话已加载的全部有效对方文本，正常聊天默认最近 80 条；滚动和调整窗口大小不会缩小范围，新到达的已加载消息自动接续，已有有效结果复用。不自动读取“查看更多”之外的历史，也不顺带开启整段画像。手选两条则只把这两条作为分析目标，后续消息不会扩充手选范围，周围消息仍可作为上下文。账号、会话或来源切换后，旧窗口授权和旧任务不能越界。
3. **单条重新分析**：右键单条文本重算。使用独立任务状态，返回相同结果也会正常结束；旧后台任务晚回来，不会覆盖刚重算的消息。切换账号、模型或清除数据后不写回旧结果。
4. **API 并发**：设置中共享分析并行数为 1–4，默认保留 1。画像、连接探测各有一个独立槽；总上限为共享档位加 2。连续两次限流降低共享并发，连续八次成功恢复到设置上限。实际收益取决于服务方，不保证远端响应时间。
5. **三个回复选项**：点击原沟通建议图标，继承当前选中聊天助手的提示词和 Skills，按当前会话上下文一次生成三个可直接发给对方的不同候选回复；再次点击会重新调用模型并替换三条。原输入区域只显示三行候选，没有手写输入或独立建议页；点击对应文本即复制，不自动发微信。始终参考同一会话中本人的表达，群聊保留成员区分。助手切换或配置变更后，旧配置的候选不能显示为当前结果；没有启用助手时提示启用，不回退通用模板。候选和右侧多轮聊天共用助手设定，结果与助手会话分别保存，不向助手对话追加候选任务。重复生成是新的模型调用，不保证相同上下文每次都产生完全不同的文字。
6. **读取与统计**：账号切换期的短暂失败两秒后可重试，扫描预算等持续性失败保留长退避。读取、分析、画像、助手预读/摘要/回复共用来源绑定，旧任务不能在 A→B→A 后复活。统计按历史结果与批次证据完整恢复，保留旧 API 画像显示及有效证据计数。
7. **桌面模型下载续传**：中断后再次下载可复用已收到的部分；服务不支持 Range 时安全重新下载，校验完整后才安装。取消不会触发自动备用下载；已经下载完整但安装失败的文件可直接重试安装。

8. **MBTI 展示**：允许有依据的持续上下文偏好，四轴独立计分，有有效分数即显示比例；100 条解锁、每轴证据数和倾向差距仍约束人格字母。未知轴不填 50/50。旧 v3 画像需要显式更新后才应用新规则。

回复选项使用独立结果缓存，只保留三条文本；缓存区分账号、会话、模型、助手及其完整配置版本。服务端读取实际助手设定和技能包，前端不能提交替代提示词。候选采用一次模型请求，不启用助手工具、文件写入或记忆修改；会话证据直接附在本轮输入中。上下文预算包含助手提示词、Skills 和相关参考资料，保留最新对话及最近本人发言的完整消息，旧上下文装不下时按完整记录裁剪。4k 配置已通过合成短对话和精简助手检查，但长技能或长消息仍可能放不下；不足时报实际错误，不静默丢弃助手设定。推理型模型的输出预算处理沿用已有协议适配，截断错误直接提示，不反复请求相同失败配置。

## 多实例

源码启动示例：`npm start -- --profile account-b`；已打包客户端可使用 `WechatVibe.exe --profile account-b`。名字限 1–32 个英文字母、数字、下划线或连字符。

不同实例可选择不同已登录账号，模型选择、端口与窗口数据隔离。默认自动账号选择仍要求唯一明确的登录账号；多账号时在账号设置中指定。相同派生数据资源只允许一个实例占用，异常退出后由操作系统回收占用。清理时若另一实例仍使用该账号，会拒绝清理。

只有默认实例提供更新入口，附加 profile 不自更新。更新或回退前必须关闭同安装的其他窗口，安装门禁也会阻止更新期间新窗口进入；不会擅自强杀无法确认归属的进程。

## 加密、备份与恢复边界

采用 PR #33 的 AES-GCM 分析结果列加密及 Windows DPAPI 密钥保护。它不等于整个 SQLite、原始聊天副本、助手历史和上下文文件全部加密。旧明文行仍兼容读取，在下一次写入时加密；不会自动重写全部历史或抹去磁盘残留。

首次打开每个分析结果库时就建立一次一致性恢复备份和受保护密钥备份，可能发生在仅查看时。这保证备份不会被本进程后续写事务阻塞；会增加磁盘占用，备份可能包含旧明文。后续打开只验证既有备份，不重复复制。

- 分析库：`.local/real-client-data/<账号哈希>.sqlite3`。
- 首次备份及清单：同目录 `<账号哈希>.pre-wv1.sqlite3` 与 `.pre-wv1.json`。
- 受保护密钥及备份：`.local/real-client-runtime/analysis-key.bin`、`analysis-key.backup.bin`。不应发送其内容。
- 清除本应用账号数据会按白名单清理该账号的分析备份与恢复撤销副本；不删除其他账号或全局密钥。

密钥缺失、截断、换 Windows 用户或密文损坏会明确报错并保留数据，不伪装成空画像、不自动擦除或换一把新密钥继续写入。

离线恢复工具为 `bridge/payload_recovery.py`，默认仅验证备份；显式 `--apply` 才恢复一个指定账号库，先阻止同安装其他进程进入、校验备份、保存当前数据撤销副本。此工具不读取原始微信库。恢复单个库不会清除加密格式标记，也不解除旧版本降级限制；继续使用支持该格式的版本。若要回到不支持加密的旧版本，需要另行验证整个安装与全部数据的一致性备份，不能把新 `.local` 直接带回旧程序。

## 验收顺序

先在一个会话检查缓存切换、手选、同值重算及画像；再切模型/账号并在运行中清除对应分析，确认旧结果不复活。随后检查指导与原助手能独立使用，再选择是否开启第二实例。保留已有数据，不需要为验收清空微信或全部分析。

功能范围、升级方式和贡献归属见 [1.3.5 更新说明](releases/1.3.5.md)。真实 API 时延与特定 GPU 性能仍需在对应环境确认。
